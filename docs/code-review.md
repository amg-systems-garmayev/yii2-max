# Проверка кода от 26.10.2026

## Исправлено

- `src/types/MessageBody.php`: `_attachments` не инициализировалось, если поле отсутствовало или список был пуст. Теперь начальное значение — `[]`; `null` тоже преобразуется в пустой список. Присваивание заменяет предыдущие вложения вместо накопления. Новый список сначала полностью преобразуется, поэтому ошибка преобразования не оставляет частично обновлённое состояние.
- Там же: отсутствующие `markup` и `text` теперь возвращают `[]` и `null`. Текст может быть `null`, например у сообщения только с вложениями.
- `src/base/Request.php`: публичные имена `message_id`, `chat_id`, `user_id` отсутствовали в safe-атрибутах. Yii `load()` игнорировал эти поля.
- `src/EventHandler.php`: `handle()` передаёт `Request`, но внутренние обработчики `command()` и `contains()` требовали `Message`, что вызывало `TypeError`. Теперь они извлекают сообщение из запроса, сохраняя передачу `Message` пользовательскому обработчику.
- `src/types/payloads/ContactPayload.php`: конструктор передавал отсутствующий `vcf_info` как `null` в `parseQuick(string)`, а отсутствующий `max_info` — в свойство `array`. Кроме того, неудачный разбор vCard может возвращать `null`, поэтому поле результата теперь nullable.

## Дополнительные найденные ошибки (не изменены)

1. **Высокий приоритет — запуск без заранее настроенного компонента.** `src/Bootstrap.php` регистрирует `garmayev\max\components\MaxComponent`, которого в репозитории нет. При обращении к автоматически зарегистрированному компоненту Yii не сможет создать объект.
2. **Высокий приоритет — несовместимость с PHP 7.4.** В `composer.json` разрешён PHP >=7.4, но `src/types/Response.php` использует union types (`Message|array|string|null`, `array|string`), которые требуют PHP 8.0. Установка на разрешённый Composer PHP 7.4 закончится ошибкой синтаксиса при загрузке этого класса.
3. **Высокий приоритет — противоречивые типы ответа.** В `src/types/Response.php` конструктор сохраняет `message` как массив или строку, `setMessage(array)` сохраняет объект `Message`, а `getMessage(): ?array` допускает только массив. После setter или строкового сообщения getter вызывает `TypeError`; методы `getMessageId()`/`getMessageText()` также не рассчитаны на сохранённый setter-ом объект и не читают вложенный `message.body`.
4. **Исправлено при проверке медиа — проверка TLS.** Из `src/MessageBuilder.php::downloadFromUrl()` удалено `verify => false`, проверка сертификатов включена.
5. **Исправлено при проверке медиа — утечка временных файлов.** При ошибке скачивания `downloadFromUrl()` удаляет созданный временный файл перед повторным выбросом исключения.
6. **Средний приоритет — аналогичные неинициализированные поля.** В `Message`, `Recipient`, `Attachment`, `ImagePayload` и других моделях остаются типизированные свойства без начальных значений. Например, `new Message(['body' => ['text' => 'x']])->getSender()` упадёт до проверки на `null` в `EventHandler::getUser()`. Для необязательных полей нужно определить nullable-контракт и согласовать getter/setter.
7. **Средний приоритет — геолокация без payload.** `MessageBuilder::location()` создаёт вложение с координатами на верхнем уровне без `payload`, но `Attachment::__construct()` безусловно читает `$config['payload']`. Передача такого массива в `Attachment` вызывает предупреждение и `TypeError`.
8. **Средний приоритет — потеря структуры клавиатуры.** `Attachment::setPayload()` сворачивает строки кнопок в один список, теряет дополнительные поля payload и не обрабатывает `open_app`, хотя соответствующий класс есть.
9. **Средний приоритет — отсутствующий интерфейс.** `src/handlers/BaseCallbackHandler.php` реализует `garmayev\max\CallbackHandlerInterface`, которого нет в репозитории. Без определения интерфейса сторонним приложением загрузка класса завершится ошибкой.
10. **Средний приоритет — секрет в журнале ошибок.** `MaxBase::send()` записывает все HTTP options, включая заголовок `Authorization` с токеном, в `Yii::error()` при исключении.
